### 🏛️ Code Architecture Overview

The site follows a static content architecture focused on academic courseware delivery. The system is segmented into source materials and generated output:

**1. Core Content Structure:**
*   **Entry Points**: Static HTML pages (`index.html`, `CV.html`, etc.) serve as the main public navigation layer.
*   **Course/Resource Modules**: Course material resides in `courses/` (and historical assets in `courses/legacy/`). These modules contain primary content and reference assets (PDFs, slides).
*   **Project Assets**: Interactive or deep-dive content is stored under `projects/`.

**2. Asset Management & Data Flow:**
The repository separates raw content from generated outputs:
*   **Source CSS**: Source components live in `assets/css/`. These modules feed into the final global stylesheet, which must **always** be read and regenerated by running `python scripts/build_css.py` to update `/styles.css`.
*   **Generated Assets**: The compiled output (the canonical look and feel) resides in assets like `/slides/`, and the compiled CSS is at `/styles.css`. **Developers should treat these generated files as read-only outputs.**

**3. JavaScript Utility Layer:**
Shared, non-module-specific utilities and theme behaviors are centralized in `theme.js` (at the repository root). Subdirectories must reference this utility using relative paths (`../theme.js`) rather than duplicating scripts.

### ⚠️ Repository Conventions & Rules

*   **File Naming**: New HTML files should use lowercase kebab-case and retain the `.html` extension.
*   **Link Handling**: All internal links (`href`/`src`) must be updated globally when assets or components are renamed or moved to maintain site integrity.
*   **Third-Party Assets**: When using external resources (CDN), always pin version numbers (e.g., `katex@0.16.9`) and adhere to the approved domain list: `fonts.googleapis.com`, `cdn.jsdelivr.net`, and `cdnjs.cloudflare.com`.
