====================================================================
1. PROJECT PURPOSE
====================================================================

This document translates the site design/layout review into an implementation-ready development plan. The goal is to make the site function as a unified academic portal rather than a set of related but visually uneven pages.

Primary audience groups:
1. Current students looking for course materials, review pages, tools, and lab resources.
2. Prospective collaborators, committees, and colleagues looking for professional information.
3. Math Club students looking for meeting information, events, engagement tracks, and honor society details.
4. Casual visitors looking for teaching resources, YouTube support, or contact information.

Primary user paths:
1. I am in a course -> find my course home.
2. I need a study tool, practice page, guide, PDF, or calculator -> open Tools & Resources.
3. I need professional information about Prof. Volk -> view About / CV.
4. I want Math Club information -> open the Liberty University Math Club site.
5. I need to contact Prof. Volk -> open Contact.

3. GLOBAL DEVELOPMENT OBJECTIVES
====================================================================

Objective A: Create a unified site identity.
- The main site should use consistent navigation, page heroes, cards, buttons, footer text, and spacing.
- Course pages should feel like members of the same course family.
- The Math Club subsite may keep its own identity, but it should still include a clear path back to the main site and should follow comparable usability standards.

Objective B: Reduce navigation ambiguity.
- The site currently uses overlapping language such as Learn, All Courses, Browse Courses, Browse Learn, and Course Home Pages.
- Standardize terminology so the user always knows where a link goes.

Objective C: Make the homepage a decision tree.
- The homepage should help visitors choose the correct path in one click.
- Course, tools, CV, Math Club, and contact paths should be visible and distinct.

Objective D: Improve page scanning.
- Long text blocks and plain lists should be converted into card grids, feature blocks, badges, or short checklist sections.
- Students should not need to read full paragraphs before finding the action they need.

Objective E: Improve accessibility and maintainability.
- All links should have visible text or accessible labels.
- Icons/images used as links should have descriptive alt text or aria-labels.
- Footer, header, nav, page hero, and card styles should be reusable.
